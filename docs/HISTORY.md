# History

Details and reasoning that don't belong in CLAUDE.md.

## Phase 1: a window that browses (2026-10-17)

- **Project shape.** `Firn.xcodeproj` is a thin app target using Xcode's folder-synced groups (files added to `Firn/` show up without editing the project file). Logic lives in the local package `FirnCore`. No XcodeGen.
- **Engine layer.** Views use `PageController` and `PageView`; only `WebKitPageController` and `PageView` touch WebKit. `BrowserEngine.makePage(dataStoreID:)` is the one place that picks the engine.
- **Data store.** Phase 1 uses one fixed, named `WKWebsiteDataStore(forIdentifier:)` (never `.default()`), so per-space stores in Phase 4 change the id, not the habit.
- **Honest address bar.** The bar shows the committed URL. WKWebView's `url` can change before a navigation commits, so cross-origin changes are only taken in `didCommit`; same-origin changes (pushState, #links) are taken from KVO.
- **Addresses.** Only http and https open. `javascript:`, `file:`, `mailto:`, other apps' schemes, and top-level `data:` are refused, both when typed and when a page navigates. Links meant for a new window open in the same page for now.
- **Search.** Google by default; Bing, DuckDuckGo, Ecosia, and Yahoo exist in code for the welcome and Settings later.
- **User agent.** Adds a Safari-style `Version/… Safari/…` suffix; without it some sites (Google sign-in among them) treat WKWebView as an embedded app view.
- **Signing.** "Sign to Run Locally" (ad-hoc). Xcode skips the hardened runtime for ad-hoc builds, so it's forced with `--options=runtime`; that in turn needs `ENABLE_DEBUG_DYLIB = NO` in Debug (ad-hoc signatures have no team, and library validation refused the separate debug dylib). Side effect: no SwiftUI Previews canvas. Once a development team is set, this can be revisited.
- **Tests from Xcode.** Adding the package's tests to the Firn scheme didn't work (Xcode found no test bundles), so `xcodebuild test` runs from inside `FirnCore`.

## Phase 2: sidebar and vertical tabs (done 2026-10-18)

- **Tab model (2a).** `BrowserStore` in FirnCore is the one place tabs and spaces change. Each `Tab` makes its page the first time it's shown, through a factory, so tests use a fake page. Closing the tab on screen shows the one below (or above, if it was last).
- **Sidebar (2b).** Custom layout, not `NavigationSplitView` (it can't collapse to 0 or peek). ⌘T focuses the address bar for a new tab; the tab only appears on Return. At rest the address bar shows just the site (IDN hosts stay in their `xn--` form); clicking in shows the whole address. Shortcuts follow Arc and Dia: ⌘W closes the tab, ⇧⌘W the window (replacing the system "Close" item), ⌘1–9, ⌃Tab, and ⇧⌘[ / ⇧⌘].
- **Drag to reorder (2c).** A custom drag in the sidebar, not `onMove`, so rows glide aside and the dropped row slides into its slot at the same speed (0.2s, `TabList.glide`); the store only moves the tab once the slide ends. Reduce Motion drops it instantly. No edge auto-scroll yet.
- **Traffic lights: let macOS place them.** A window without a toolbar gets the old compact spot (about 16pt from the corner); every app with a toolbar, even an invisible one, gets the roomier spot. Moving the buttons by hand didn't hold: macOS lays the title bar out again on title changes and undid it. Firn gives the window an empty `NSToolbar` (like Electron's `hiddenInset`) and lines the sidebar's top row up with where the lights land, measured, not guessed.
- **Resize, hide, and peek (2d).** Drag the gap (200–360pt); pulling past 200pt hits a wall, and 60pt further snaps the sidebar away (`SidebarSizing` in FirnCore, tested). Also ⌘S, View → Hide Sidebar, and a sidebar button after the traffic lights. Reload moved into the address bar, as in Safari, so the top row fits at 200pt. What made it smooth, after two rough tries:
  - *One curve, frame by frame.* SwiftUI doesn't animate an `NSView`'s real frame; it snaps while shapes around it glide. So the page's inset and the traffic lights are driven by `Animatable` modifiers whose `body` runs every frame (checked: about 60 updates a second, on the sidebar's exact curve). The page truly resizes with the sidebar, like Dia; the gap between them stays 8pt throughout.
  - *Traffic lights move with the sidebar.* Firn shifts macOS's own buttons, and puts them back when macOS re-lays out the title bar (it does on every resize; a frame-change notification catches it, and the shift is reapplied on the next turn, because doing it mid-layout doesn't stick). Hidden when slid away, so they can't be clicked. Left alone in full screen.
  - *The grab strip is its own layer.* Nested in the sidebar, the sidebar's hit area cut it off and clicks in the gap fell through to the window-drag area. An AppKit view gives a dependable resize cursor beside the web view.
  - *Peek is a card* 4pt inside the window, just outside the page's 8pt, its corners concentric with the page's (as in Dia). One AppKit tracking area decides peeking by pointer position alone (SwiftUI hover reported neighboring areas in no fixed order, leaving dead zones): the 8pt left edge brings it out; it stays over the card plus 16pt; it hides 0.15s after the pointer moves away inside the window, or 1s after it leaves the window (forgives overshoots, still tucks away beside another app). ⌘L/⌘T while hidden hold it out until typing ends.
  - Motion: 0.2s, `timingCurve(0.3, 0, 0.2, 1)`; Reduce Motion fades. Width and hidden state aren't saved yet (Phase 3).
- **New windows become tabs (2e).** A link meant for a new window, or a popup after a click, opens as a tab below its opener (after any it opened before) and is shown. Firn builds the new page from the configuration WebKit hands over and returns it, rather than loading the address in a fresh page, so `window.opener` keeps working (sign-in popups report back through it). The popup must use its opener's data store (checked by identifier) or nothing opens. A popup that calls `window.close()` closes its tab and hands back to its opener; ordinary tabs can't close themselves. `javaScriptCanOpenWindowsAutomatically` is off (on by default on the Mac), so sites need a click to open one. Pages reach the store through one hook, `PageController.onRequest`.
  - *⌘-click and middle-click* open in a background tab; ⇧ brings it forward. The tab loads the first time it's shown, so its row shows the site's name until then. Loading it right away was tried first: pages loaded before they'd ever been on screen sat blank for 5–10 seconds when shown (seen on Wikipedia; typed and plain-clicked pages were fine). The likely cause turned out to be zero-size layout (below); background loading could be tried again with a real starting size. A page can fake a ⌘-click in script, so the click only counts if AppKit saw a real one on that page within the last second (a local event monitor); each click is used once.
- **Tab switches froze on long pages.** Measured with temporary timing logs and `sample`: SwiftUI sizes a re-shown web view at 0×0 before its real size, so WebKit laid a whole Wikipedia article out twice, and AppKit's main thread waited (up to WebKit's ~250ms) for the page to be ready, freezing the window 300–400ms per switch. `PageView` now wraps the web view in `PageHolder`, which passes on only non-zero sizes; afterwards, no freezes. A diagnostic recipe for next time: an `os.Logger` with its own subsystem, read with `/usr/bin/log show` (zsh's `log` is a builtin), plus `sample <pid> 25` while David reproduces.
- **Polish after David's check.** The peeking card's glass edge and shadow follow `sidebarCollapsed`, not `isPeeking`, so they stay with the card for the whole slide; hidden, it slides out far enough that its extra width and shadow don't show. **Window dragging:** macOS drags the window from the whole title-bar band (about 52pt with the empty toolbar, 28pt without) even over the web view, before the app sees the click; `mouseDownCanMoveWindow` and the private `_opaqueRectForWindowMoveWhenInTitlebar` didn't stop it. What works: `PointerTracker` turns `window.isMovable` off while the pointer is over a `PageHolder`. Blank sidebar space moves the window, as in Dia (`WindowDragArea` behind the sidebar and behind the tab list, stretched to its height). Invisible helper views return nil from `hitTest`, so the frame strip drags too. Checked with a scratch tool that posts real mouse drags (CGEvent) and compares window positions; place the window mid-screen first via Accessibility, or screen edges skew results.

## Phase 3: Basecamp, groups, and persistence (done 2026-10-19)

- **Model and saving (3a).** `BrowserStore` gained pins and Basecamp (up to 12 per space). Pinning or adding to Basecamp makes the tab's address its home; "Go back to home" returns there. Closing a pin or tile lets its page go and leaves it resting in place; the window then shows the tab seen most recently. Unpinning (or removing from Basecamp) an awake tab moves it to the top of the everyday tabs so its page isn't lost; a resting one simply goes. Links from a pin open at the top of the everyday tabs. ⌘1–9 and ⌃Tab count the sidebar top to bottom: Basecamp, pins, tabs.
  - *One file:* `Application Support/Firn/session.json` in the sandbox container (`Session`, `SessionFile`), versioned, written atomically. A file that can't be read, or comes from a newer Firn, moves to `session.broken.json`, and Firn starts fresh.
  - *When it saves:* `SessionSaver` watches the snapshot with Observation and saves about a second after a change, plus once at quit. Nothing runs while idle.
  - *Restoring is defensive:* only http and https addresses come back, tabs must belong to a known space, ids are unique, and Basecamp is trimmed to 12. Only the tab on screen loads at launch.
  - *Address only:* back/forward history doesn't come back (David's choice); WebKit's `interactionState` could add it later.
  - *Sync-ready:* each tab record's `lastChangedAt` moves only when the record really changed (compared against the last saved record). The file stores dates to the second.
- **Basecamp grid (3b-i).** Redone on Opus after a first, square-tile try looked poor. Modeled on Dia's tiles in Firn's style: wide, short tiles (40pt tall, 9pt corners, 6pt apart), the longest row filling the sidebar. `BasecampLayout` (FirnCore, tested): as few rows as fit (4 across at most, tiles at least 52pt wide), rows balanced to differ by at most one (5 is 3 + 2, never 4 + 1); a narrow sidebar drops to 3 across, so 4 becomes 2 + 2; shorter rows keep the same tile width and start at the left.
  - *Look:* tiles are Liquid Glass on macOS 26+ with a cool snowy tint and a crisp 0.5pt frosted edge ("frosted ice," not bubbly); before 26, a frosted fill with a lit rim. Fine on the plain frame: the sidebar isn't glass, so no glass on glass. The chosen tile takes the site's color, quieter than Dia: page white with a 14% wash (24% dark), a 1.5pt outline, and a faint glow. Hover brightens, press sinks to 97%, no bounce; Reduce Motion and Reduce Transparency respected.
  - *Icon:* until 3c, an 18pt rounded square in one of the eight space colors (picked from the host with FNV-1a, stable across launches) with the site's first letter. The site's color also drives the chosen tile; 3c's icons can supply their own color later.
  - Right-click a tile: Go Back to Home (only when away), Remove from Basecamp, Close. Right-click an everyday tab: Add to Basecamp (greyed out at 12).
- **Site icons (3c).** David approved the extra request (2026-10-18). After each page load, a script in Firn's own `WKContentWorld` lists the page's `<link rel=icon>` tags (the page can't see or change it); everything it returns is checked field by field (`SiteIcon` in FirnCore, tested). Order: the page's icons closest to 64px, then `/favicon.ico`, then Apple touch icons (full-bleed squares, so last); SVG is skipped (ImageIO can't read it), and so are icons whose `media` is for the other light/dark mode.
  - *The request:* an ephemeral `URLSession` with no cookies, cache, or saved credentials; the page's user agent (so it doesn't announce "Firn"); 10s idle and 15s total timeouts; 512 KB at most; https pages only fetch https icons, and redirects can't drop to http. A page can't point Firn at the local network (localhost, `.local`, IP addresses) unless it lives there itself, since this request comes from Firn, not WebKit.
  - *The image:* only PNG, ICO, JPEG, GIF, WebP, and BMP; anything over about 1024 × 1024 is refused before decoding (decompression bombs); the best size in a multi-size .ico is picked; ImageIO redraws it as a fresh PNG of at most 64px. Only that PNG is kept or shown.
  - *Kept on the tab* (`TabRecord.icon`, base64 in `session.json`), so icons are per space by construction and go when the tab does. Restored icons must be small PNGs. A woken tab shows last time's icon until its page finds one, but only while it's on the same site; moving to another site clears it at commit.
  - *Shown* at 16pt in tab rows (globe until found) and 18pt on Basecamp tiles (the letter tile until found). Decoded images are cached, so the sidebar doesn't decode on every redraw.
  - *Icons that change after loading.* GitHub's page names its light icon and swaps in the dark one by script after Firn had read the list, so dark mode showed the black octocat. A watcher in Firn's world (a `MutationObserver` on the page's `<head>` plus the light/dark media query) posts one word, "changed", to a handler that exists only in Firn's world; it counts only from the main frame and the page's real origin. Firn looks again a second later and fetches only if the list changed. Also covers icons that change while open (unread counts). One watcher serves every page, because popups share their opener's content controller and a handler name can't be added twice.
  - *The real GitHub bug:* the script capped the page's links at 40 before looking for icons, and GitHub has 144 links with its first icon at number 98 (stylesheets come first), so Firn always fell back to `/favicon.ico` (the black octocat). Found by pulling the saved icon out of `session.json` (it matched `/favicon.ico` byte for byte), then testing the script and the download on their own. The script now selects icon links first and caps those; a test runs the real script in a WKWebView on a page with 120 stylesheets ahead of its icon.
  - *No fading for tiles that haven't loaded yet* (David, 2026-10-18): as in Dia. A faded tile looks broken, or promises a slow load before anything happens.
- **Tile colors from the icon (3c).** The chosen Basecamp tile now takes its icon's own color. `IconColor` (FirnCore, tested) draws the icon at 32px, ignores see-through, grey, near-white, and near-black pixels, and lets the rest vote by hue (weighted by how colorful they are); the strongest hue and its neighbors are averaged. It's then calmed into the space colors' range (saturation 0.28–0.5, brightness 0.6–0.8), so YouTube's red becomes a soft terracotta. Under 5% colored pixels counts as no color: black, white, or grey icons (GitHub, Apple) get a warm neutral (`faint`), David's pick (2026-10-18), not a made-up color. No icon yet: the address's color, matching the letter mark. Worked out once per icon and remembered; the color cross-fades when an icon arrives.
  - *The glass ring* (after comparing with a video of Dia, 2026-10-18): the chosen tile had lost its frost (solid page white under a flat 1.5pt line). Now it keeps the same glass as the others, with a wash of the main color (stronger at the top left), a 2.5pt ring of slightly see-through colored glass, and a bright 0.5pt lip of ice just inside it. The ring follows the icon: `IconColor` splits the icon into eight slices around its center, finds each slice's main hue the same way, calms it, and lets empty slices borrow from the nearest one; the tile draws them as an angular gradient (no blur filter). So Gmail's ring runs through its own soft red, yellow, green, and blue, and one-color icons get an even ring. Dia's dark fill for GitHub was left out: too loud.
  - *Dark mode, calmer* (David, 2026-10-18): the glow and wash dropped to 18% in dark (from 35% and 28%), so the tile reads as a crisp ring around clear glass, not a pink haze.
  - *For later:* if the window itself becomes translucent (design principle 4), the tiles would be glass on glass. Revisit the tile material then (likely one `GlassEffectContainer`, or frosted fills instead of `.glassEffect`). David likes how Dia's tiles look etched out of the background glass rather than set on it: worth trying then, together with space colors.
- **Pins dropped for groups (2026-10-18).** David, after using Dia: three tiers (Basecamp, pins, tabs) are one more idea than normal people need, and pins are Arc's most confusing part (they look like tabs, but closing one doesn't close it). Now two tiers: what's kept (Basecamp tiles, then groups) on top, loose tabs below, which archive as before. No divider line (David): the groups' frosted cards already mark the boundary, so the sidebar stays one clean column of address bar, tiles, and tabs. Putting a tab in a group is the "keep" gesture, so grouped tabs never archive; they're ordinary tabs otherwise (no home address, closing really closes, ⇧⌘T brings one back). Only tiles keep a home address and rest when closed.
  - *Considered and left out:* Basecamp tiles shared by every space (it breaks "each space is its own browser": a Gmail tile in Work is a different account than in Personal); archiving after 12–24 hours (a day off shouldn't wipe tabs; 7 days of use stays); Dia's always-visible ✕ on a group's header (one stray click closes the whole group; it's in the right-click menu instead).
  - *Order:* groups always sit above the loose tabs, like Dia, and can be dragged into any order. A new group appears at the bottom of the groups, right above the loose tabs, so the tab barely moves (Dia puts it at the top). Groups of one are allowed.
  - *Code:* 3a's pins existed only in `BrowserStore` and its tests (no pins UI yet), so `Tab.Place.pinned` and the pin calls go when groups come in.
- **Groups: model and saving (3b-ii).** Pins are gone from the code (`Tab.Place` is `basecamp`, `open`, or `archived`). A `TabGroup` is an id, space, name ("New Group" to start), and folded flag; the store keeps groups in order, and each tab has an optional `groupID`. Grouped tabs are ordinary everyday tabs. The store can start a group with a tab (below the other groups), drop a tab onto another (join its group just after it, or start a group of two), move tabs into, within, and out of groups (out means the top of the loose tabs unless dropped elsewhere), and rename, fold, reorder, ungroup, or close a group. A group ends when its last tab closes or leaves; adding a grouped tab to Basecamp takes it out. Basecamp tiles never join groups.
  - *Links from a grouped tab* open at the top of the loose tabs, like links from a tile (David, 2026-10-18): joining a group is a choice, so links shouldn't fill one up. Later, links from tiles (and maybe groups) should open as a Lookout first.
  - *Order:* Basecamp, each group's tabs, then the loose tabs. ⌘1–9 and ⌃Tab skip folded groups. Closing a grouped tab shows its neighbor in the same group.
  - *Saving:* `session.json` gains `groups` (with order and a last-changed time that only moves on a real change) and each tab's `groupID`; files without them load as having no groups. Restoring checks groups like tabs: known space, unique id, a tidy one-line name of at most 100 characters (blank becomes "New Group"), only everyday tabs grouped and only into a group of their own space; groups left empty are dropped.
- **Groups: the look (3b-ii).** Approved from a mockup (David, 2026-10-18). Each group is a card under New tab and above the loose tabs: the tiles' frosted glass (Liquid Glass on macOS 26, the same fill and rims before it, solid with Reduce Transparency) washed with the space's color at 10%, 14pt corners so the 10pt rows nest 4pt inside. The name line is 30pt (shorter than a 36pt tab row, so it reads as a label): a 6pt space-color dot, the name in 12pt medium, and the fold arrow just after the name, as in Dia. Clicking the line folds; the close button shows only on hover. Cards are 6pt apart, with a little extra air before the loose tabs. Right-click a group for Rename, Ungroup, and Close Group; right-click a tab for New Group with This Tab or Remove from Group. A new group opens its name for editing straight away. Tabs reorder by dragging within their own group for now.
  - *Considered and left out:* a count on folded groups (David: noise); indenting tabs inside a group (Dia indents because its card only appears on hover; Firn's card is always there, so an indent would say the same thing twice and cost 14pt of title).
  - *Close safety:* the hover close button means one stray click can close a whole group, so ⇧⌘T will bring a closed group back whole. ⇧⌘T doesn't exist yet even for single tabs; it's its own step.
- **Groups: one shared order (3b-ii).** Groups and loose tabs now sit in one list, so a group can be anywhere among the tabs (David, 2026-10-19). There's no second list to keep in step: the tab order Firn already saves is the one order, and a group's tabs always sit side by side in it, so a group is wherever its tabs are (`BrowserStore.tabListItems`). Every change keeps them together (links opened below a loose tab stop short of a group's tabs), and restoring pulls a group's tabs back to where its first one is if a file has them apart.
  - *A new group appears where its tab already was*; a tab taken from one group to start another lands just below the old group. Moving a group moves all its tabs.
  - *For now,* tabs taken out of a group, ungrouped tabs, links from tiles and grouped tabs, and tiles removed from Basecamp go to the top of the list (above any group). The top-or-bottom setting comes next and changes that one place (`topOfTabList`).
  - *Dragging:* a card's top edge (above the middle of its name line) and bottom edge (a quarter row) count as above or below the group, so a tab can be dropped between two groups or right above one without joining it; a folded card's top and bottom quarters do the same. Spacing is unchanged: a card has 6pt of air above it and a little more below.
  - ⌘1–9 and ⌃Tab follow the list as shown.
- **New tabs at the top or the bottom (3b-ii).** A setting in a new Settings window (⌘, or Firn › Settings…): "New tabs open" At the top / At the bottom, bottom by default (David, 2026-10-19). It's an app preference (UserDefaults, inside the sandbox), not part of the session, and applies to every space. The New tab button moves with it: just below Basecamp, or below the last tab or group. ⌘T tabs, links from Basecamp tiles, tabs taken out of a group, ungrouped tabs, and tiles taken off Basecamp all arrive there (`BrowserStore.arrivalIndex`). When a tab comes on screen the list scrolls just enough to show it.
  - *Links from a grouped tab now open inside its group, right below it* (David, 2026-10-19, as in Dia), replacing 2026-10-18's "top of the loose tabs." Links from a loose tab still open right below it. Links from tiles will open as a Lookout first once Lookout exists.
- **⇧⌘T: reopen closed tabs and whole groups (3b-ii).** File › Reopen Closed Tab (it reads "Reopen Closed Group" when a group is next). Each press brings back the newest closed thing in the current space, where it was, and shows it: a loose tab at its old place in the list; a grouped tab back inside its group (opened if folded), or loose where it was if the group has gone since; a closed group whole, with its name, open, showing the tab that was on screen. Closing a group's last tab ends the group, so that's remembered as the group. The page reloads from its address (back/forward history isn't kept, as with Basecamp tiles at rest).
  - *Not remembered:* Basecamp tiles (they stay put, resting), popups that close themselves (a finished sign-in), and tabs that never had an address.
  - *Kept while Firn runs only*, the newest 30 across spaces, not saved to disk. Each item only comes back in its own space, so nothing crosses between spaces; deleting a space (Phase 4) must drop its items too.

It fades in over 200ms. Cancelled and replaced loads (NSURLErrorCancelled, WebKit's 102 and 204) are ignored. `LoadError` (FirnCore) holds the address and a plain reason, and its words are tested. While it shows, the tab's address, title, and icon are the failed site's, never the old page's (the old page is still underneath, hidden). A tab that sleeps or is saved rests at the failed address, so it tries again on waking. No "visit anyway" for unsafe connections, on purpose.
