Downloads on the iPhone

A draft for step 1 of "Downloads to Files" (docs/IOS-PLAN.md, phase 6). Today the iPhone refuses downloads, so a page can't quietly fill the phone. This is how they come back: nothing is saved until you tap, you can always see what's coming in, and every file lands in one place you can find in the Files app.

Two choices are yours, in the bar below. Each scene shows light and dark.

The question
Files go to

1. The question

Tap a download link and Firn asks first, naming the file, the site it really comes from (never what the page claims), and its size when the site says. Download saves it; View shows it as the page instead (only for what the phone can show, like a PDF); Cancel saves nothing. WebKit writes not a byte before the tap.

  • iOS's alert (my pick): the same alert Firn already uses when a page says something (headed by the real site), and Safari's way. A page can't draw over it or imitate it convincingly, which matters for a question about saving files.
  • Firn's card: the hold menu's frost, rising just above the bar. Calmer and more Firn, but a page can draw something that looks like it.

2. While it saves

A quiet frosted pill floats just above the bar: a ring filling in the space's color, the file's name, and how far along it is. The page stays fully usable; the pill never covers the bar. Tap it to open Downloads.

3. Saved

The ring becomes a check and the pill says Saved to Files. It holds a few seconds, then fades. Tap it before it goes to open Downloads. A failed download says Download failed the same way, in the same calm words, no alarm.

4. The way back in

While this space has downloads, the page menu (the ••• in the field) gets a Downloads row at the end, with a quiet second line: how many are saving, or how many there are. The command bar gets a Downloads action too. When the space has none, neither shows (as on the Mac, where the button is there only while the space has downloads).

5. Downloads

A sheet on warm paper, like Settings and New Space. Only this space's downloads (each space is its own browser). Tap a finished file to open it right there (Quick Look); the ↑ shares it. A saving file shows its progress and an ✕ to stop it. Clear takes finished ones off the list; the files stay. Open in Files goes straight to the folder. The list is forgotten when Firn quits, as on the Mac; the files never are.

6. Holding a download

Firn's own hold menu, kept short: Share…, Show in Files, and Delete (in terracotta: it removes the file itself, after a plain "Delete this file? It can't be brought back"). Taking it off the list without deleting is what Clear does.

Where the files go

On My iPhone › Firn › Downloads (my pick). Files stay on the phone, as Firn's promise says. They show in the Files app under Firn's own folder, can be moved anywhere from there, and go away if Firn is deleted (Files warns before that). Every space's files share this one folder, as on the Mac, where they all go to Downloads.

iCloud Drive › Downloads, as Safari's default. Handy across devices, but every download would go up to iCloud, which changes "your data stays on your device": Firn would have to say so. It also needs an iCloud container document setting and works only when signed in to iCloud, so Firn would still need On My iPhone as a fallback.

Either way: no setting to pick a different folder (calm over clever), and nothing about downloads ever leaves the phone through Firn.
